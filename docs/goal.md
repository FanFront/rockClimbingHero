# RockClimbingHero · 下一轮 Codex 迭代目标

> **Phase: 中文像素探险 RPG UI 重构**
> 
> **只支持 Android。请直接实现代码并提交 GitHub，不要只产出方案。**
> 
> 最重要的要求：**更像游戏、默认中文、少滚动、少文字、大面积像素美术。**
> 
> 时间优先花在真正能看到、能操作的界面上，**不要花大量时间编写测试、冗长文档或过度抽象代码。**

## 给 Codex 的开发任务

你负责将已有 `rockClimbingHero` 改造成有吸引力的 **Expedition RPG（山地探险 RPG）**。先快速阅读 `App.tsx`、`src/art.tsx`、`src/domain.ts`、`src/storage.ts`，然后直接动手开发。

### P0 — 游戏化视觉与布局（最高优先级）

- 将首页改成**像素营地场景 Hub**：远山、松林、帐篷、篝火、显眼的攀岩者角色和可点击的地点/功能入口。**场景占主要屏幕面积，不再用长篇卡片堆叠。**
- 用 **营地 / 任务 / 角色 / 地图 / 记录** 作为主导航。核心页面适配 Android 竖屏，优先一屏完成主要操作；详情用弹窗、标签切换或局部展开。小屏/无障碍情况下可以必要滚动，但不能遮挡操作。
- 界面强调 RPG 氛围：像素图标、经验条、任务牌、地图节点、技能节点、徽章、升级提示；**每屏文字尽量短，次要说明点开再看**。
- 强化**真实运行的原创像素资源**（不是只有概念图）：明显改善 `src/art.tsx` 中的角色、营地、世界地图、五属性和八技能图标；统一冷青夜色+暖金篝火配色。图片要清晰、适配不同分辨率，避免拉伸和模糊。
- 做少量真实的游戏反馈：完成训练后显示 `+XP`、等级/技能变化、地图节点解锁；反馈只能来自实际记录。

### P1 — 中文完整可用

- 默认**简体中文 zh-CN**，设置中可切换 English，并记住语言选择。
- 用户看见的按钮、五维属性、问卷、技能、任务、记录、提示和错误信息使用统一文案字典；内部数据 ID 保持原样，**不要翻译存档枚举**。
- 中文 UI 用清晰易读的系统字体，不要把中文大段内容强行用像素英文等宽字体渲染。尽量改成 2–8 字短标签。

### P2 — 核心玩法简化，但功能必须保留

- **角色：** 大幅人物立绘 + 等级/XP + 五维；属性/技能/装扮/成就用标签切换，点击技能节点看详情。
- **任务：** 今日主任务 + 少量备选任务，卡片只显示图标、名称、时长、奖励；点开最多 3 步说明。
- **地图：** 可点击的像素探险路线和解锁节点，根据已有**真实训练/成长记录**推进。
- **记录：** 两步内进入快速训练记录，抱石难度、尝试次数、完攀、时长优先；更多参数和备注折叠。提交后立即显示真实获得的奖励。
- **问卷：** 五题改为逐题展示，用户回答后生成初始角色；支持重复评估并保留历史。
- 保留已有：离线存档、XP 与等级、五属性、八技能、训练日志、重评历史、自我证明和疼痛/恢复保护。**不要清空旧存档，也不要将游戏 XP 直接当成真实身体能力。** 如扩展数据结构，兼容现有 `AppData.schema=1`。
- 受伤/疼痛时不得推荐加大训练负荷或用奖励诱导硬练；休息不受惩罚。

## 实施方式

优先复用现有 Expo + React Native + TypeScript + SQLite 和 SVG 资源；不增加 iOS、后端、账号或在线 AI 依赖。避免大规模与目标无关的架构重构。先实现**完整可交互的营地首页及中文短流程**，再将统一美术延展到角色、任务、地图、记录页面。

**建议直接分阶段提交：**
1. 中文字典 + 营地单屏游戏化首页。
2. 角色/任务/地图/快速记录重构。
3. 像素素材优化 + 轻量升级反馈 + 收尾。

## 最小验证要求（不要把主要时间用在测试上）

- 只做必要检查：`npm run typecheck`，并确认 Android 能启动或 APK 能构建（在环境允许时）。
- 手动快速走通：首次建角 → 记录一次训练 → XP/技能更新 → 重启后数据仍在；确认中文无明显截断。
- **不要新增大量单元测试、端到端测试、复杂 CI 或测试文档。** 遇到明显阻断错误才修复；既有业务规则测试可保留，不要求扩充。
- 环境无法执行 APK 构建时，在提交说明中明确写出未验证的部分即可，不要因此停止功能开发。

## 完成标准

启动 Android App，用户第一眼看到的是**精美像素山地营地和自己的探险角色**；默认中文；常用任务、角色、地图和训练记录都能通过短路径完成；主要功能无需长篇滚动；原有存档和真实成长记录不丢失。全部修改提交到仓库，并在最终回复中提供提交 SHA、完成的功能及尚未验证的事项。

**不要写长篇分析。开始修改代码。**
