# RockClimbingHero · 下一轮 Codex Goal
## Phase：真实训练驱动的随机 RPG 委托 + 细粒度成长 + 线路图鉴

> **Android only / 简体中文优先 / 继续像素探险 RPG 风格。直接写代码并推送 GitHub。**
>
> **最高优先级：用户打开 App 有“接任务 → 去攀岩/训练 → 自动结算 → 角色变强 → 收集线路”的游戏循环，而不是自己填写一堆数字。**
>
> **少文档、少测试、多做真实功能。** 保留现有营地/地图/角色 UI、双语、SQLite 离线存档及数据；不得清空旧存档。

### P0 — 每日 / 每周随机委托（这一轮最重要的功能）

- 建立**可扩充的任务模板池**，分为：**指定技术动作训练**（静音落脚、侧旗、转髋、路线预读、难点拆解等）、**完成指定攀岩线路**（难度范围 + 岩壁类型：斜板/直壁/仰角等）、**力量训练**、**拉伸/灵活性训练**、**恢复/休息**。每类给出清晰可实现的目标、条件和**预设奖励**。
- 每天生成 **1 个主线 + 2～3 个可选委托**；每周生成 **2～3 个周常委托**。玩家能自由选攀岩或恢复日，不能因为休息被惩罚。避免连续重复同一种目标；兼顾训练频率、最近已完成线路、能力等级、近期疲劳/疼痛和适度渐进，不为了游戏强行要求突破极限。
- 为任务生成**短而有风味的随机故事文字**，如「松火营地的老向导想看看你能否悄无声息地踏过回声岩壁……」。用**离线词库/模板 + 组合变量 + 固定 seed** 生成，不增加 LLM API 依赖；一天/一周生成后持久化，切页/重启不能随机改变；中英双语，中文默认。
- 任务卡像 RPG 悬赏板：像素插画/徽记、任务名、目标（最多 1～2 行）、进度、奖赏、倒计时；点击弹出详情，少滚动、少解释。玩家可以查看今天、这周和已完成委托。
- **不是“点击完成”就领奖**：已记录的训练、动作练习及已完攀线路应自动匹配任务条件、更新进度并结算。相册不是必需的作弊检测或完成凭证；用户可直接记录真实训练。线路任务必须是真正记录了 sends > 0 的完攀，尝试不算完攀。暂不接健身房 API/传感器。
- 用当地日历日和周计算任务周期（周一开始），给每个周期任务稳定 ID；已领取的任务、累计进度、已结算奖励和过期历史必须持久化。**同一任务完成奖励只发一次**，重复打开、修改日志、重新计算均不可刷奖励；删除或更正记录时要同步重新核算已获得的任务奖励/成长，不能造成永久虚假数据。

### P0 — 能力成长：从“只加 XP”升级到“属性经验条”

- 保留现有角色等级 XP 和五属性 **PWR 力量 / TEC 技巧 / END 耐力 / MOB 灵活 / MND 心态**；额外实现每个属性的**小粒度训练成长进度条**（例如当前游戏属性点数 + `36/100` 成长进度）。**不是每完成一个任务就直接 +1 点。**
- 每个委托模板事先定义奖励 `XP + 属性成长进度`，根据任务目标发给相关属性；例如静音落脚 `XP +25, TEC +12/100`，周任务完攀 `XP +70, TEC +24/100, MND +10/100`，主动拉伸 `MOB +8/100`。以上数值为初始平衡参考，集中在可调整配置中。
- 达到进度阈值才提升 **1 个游戏属性点**，保留溢出进度；弹出简短像素奖励动画/属性条上涨/升级播报。任务和会话奖励必须有明确来源记录，不能因为 UI 重渲染重复发放。
- **区分游戏成长与真实能力**：原有五题自评与重测记录不能被“假装自动测得更强”。自评仍代表主观状态；新进度是**游戏训练成长**，分别显示或明确标注，不要把进度条包装成真实力量测试结果。
- 力量、技术、攀岩线路、拉伸分别给对应成长；休息日可以给少量 XP / 恢复探索进度或装饰性奖励，**不要声称单纯休息会直接提高握力/攀岩能力**。对异常大量重复记录做合理奖励上限；疼痛状态只能建议休息/不加重症状的轻活动，不能给加码攀岩任务。

### P1 — 线路图鉴：真实完攀历史 + 原相册图片/视频关联

- 增加**独立线路记录**（不只是总 Session 的尝试/完攀数字），可从训练记录一键创建：**线路名称/编号（可选）、岩馆/区域（可选）、难度、岩壁类型、完攀/未完攀、尝试次数、时间、感想/个人 beta**。支持同一训练会话关联多条线路；图鉴按最近/难度/类型筛选，点卡片查看详情和媒体。
- 用户从系统相册/文件选择器选取**一张或多张图片、视频**绑定线路；**只保存原媒体引用 URI、类型和必要元数据，不复制照片/视频到 App 私有目录，不上传云端**。记录创建、编辑、删除时能关联/解除关联。
- **Android 重点**：采用能提供可持久化访问权限的系统文档选择方式（例如 `ACTION_OPEN_DOCUMENT` + `content://` + `takePersistableUriPermission`），若 Expo 现成选择器不能可靠保留原始媒体 URI，允许写小型 Android 原生模块/Expo config plugin；**不能用易失的临时 cache 文件假装永久相册引用**。确保重启后可打开；媒体被移走/删除/权限失效时显示“媒体不可用，重新选择”，不得导致线路或存档丢失。只在用户主动操作时请求必要权限。
- 线路支持**缩略图/预览、原相册视频播放/系统打开**；媒体只是引用，原文件由用户管理。无需照片才能保存完攀记录，也不要为媒体添加大文件上传/转码后端。
- **保持现有功能正确**：旧 Session、XP、最佳 V 完攀、自评历史不丢失；必要时实现从 `AppData.schema=1` 到新结构的安全迁移或独立版本化存储；旧记录仍能查看。难度先完整支持当前 V 体系，其他岩馆颜色/自定义难度可选但不伪造 V 等价；难度任务只用能可靠比较的难度匹配。

### 实现顺序与重点

1. **先做游戏闭环**：任务模板 + 稳定生成/保存 + 从真实日志匹配 + 奖励幂等结算 + 细粒度属性条 + 营地奖励视觉。
2. **再做线路图鉴**：一场多线路、时间/感想、相册原媒体 URI 持久授权、照片/视频预览与失效重选。
3. **最后打磨**：每日/每周悬赏板、任务随机风味、完成弹窗、角色属性动画、地图/图鉴小图标。保持简体中文主界面、可切英文、少字多画面、少滚动；功能先于装饰。

尽量沿用现有 React Native + Expo + TypeScript + SQLite + SVG。不要实现 iOS、在线 AI、复杂账号同步或大型后端。可以拆 `domain` 为更清晰的小模块，但不为了架构洁癖重写可用功能。

### 最小测试（严禁测试喧宾夺主）

- 必需：`npm run typecheck`；环境允许时走一次 Android 启动或 APK 构建。
- 只快速检查 3 条关键路径：① 任务生成跨重启不变、完成后奖励只发一次；② 属性条增长/进位且重启保持；③ 关联原相册照片/视频后重启可打开，失效时能重选。
- **不要堆单测、E2E、复杂 CI、长篇测试报告。** 现有测试能跑就保留，少量关键 bug 修复即可；遇到构建环境问题简述即可，不要挤占功能开发时间。

### 最终交付

直接在 GitHub 提交可运行代码，报告 commit SHA、实现的主要功能与未验证事项。**完成标准：用户真正能接随机日/周任务，做真实攀岩或训练后自动领 XP/属性成长奖励，打开角色面板能看到小进度条上涨，并在像素线路图鉴中查看自己关联的相册照片/视频。不要只写设计文档。**
